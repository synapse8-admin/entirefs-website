4. PERFORMANCE AND PAGE-SPEED OPTIMISATION
==================================================

Optimise the website for fast loading on real mobile devices and slower mobile connections.

Images:

- Audit every image used by the website.
- Compress oversized images without visible quality loss.
- Use WebP or AVIF where supported and retain an appropriate fallback where required.
- Use responsive image sizing with `srcset` and `sizes` where useful.
- Never serve an image materially larger than its displayed dimensions.
- Add accurate intrinsic width and height values to prevent layout movement.
- Lazy-load below-the-fold images.
- Do not lazy-load the primary above-the-fold hero or Largest Contentful Paint image.
- Give the primary hero/LCP image an appropriate high fetch priority where beneficial.
- Ensure decorative images have empty alt text.
- Ensure informative images have meaningful alt text.
- Preserve the visual quality of logos and brand assets.

Fonts:

- Prefer locally hosted WOFF2 files where licensing and the existing implementation allow it.
- Remove unused font weights and character sets.
- Preload only fonts that are genuinely required above the fold.
- Use `font-display: swap` or an equivalent non-blocking strategy.
- Provide sensible fallback fonts.
- Prevent font loading from causing layout shifts.

CSS and JavaScript:

- Minify production CSS and JavaScript.
- Enable tree shaking.
- Split large JavaScript bundles where appropriate.
- Route-split or lazy-load substantial page-specific code where supported.
- Defer non-critical scripts.
- Delay non-essential third-party widgets until they are needed, visible or the browser is idle.
- Do not delay anything required for accessibility, navigation or core page content.
- Remove unused CSS and duplicate rules.
- Avoid render-blocking resources where possible.
- Inline only genuinely critical CSS when it provides a measurable benefit.
- Avoid excessive DOM size and unnecessary component nesting.
- Reduce expensive scroll, resize and animation handlers.
- Debounce or throttle repeated event handlers where required.
- Avoid loading the same library more than once.

Caching and delivery:

- Enable Brotli or gzip compression where the deployment platform supports it.
- Apply long-lived immutable caching to versioned static assets.
- Use short or revalidation-based caching for HTML.
- Do not apply immutable caching to HTML files.
- Ensure updated deployments do not continue serving obsolete HTML.
- Use preconnect or DNS prefetch only for essential third-party origins.
- Do not add unnecessary preconnect entries.
- Remove mixed HTTP/HTTPS resources.
- Ensure all assets load over HTTPS.

Visual stability and responsiveness:

- Reserve dimensions for images, videos, iframes and embedded widgets.
- Prevent late-loading banners, review widgets, fonts and images from shifting content.
- Ensure sticky elements do not unexpectedly move or cover page content.
- Avoid animation of layout properties where transform or opacity can be used.
- Respect `prefers-reduced-motion`.

Performance targets for the main public pages:

- Lighthouse Performance: 90 or higher on mobile and desktop
- Lighthouse Accessibility: 95 or higher
- Lighthouse Best Practices: 95 or higher
- Lighthouse SEO: 95 or higher
- Largest Contentful Paint: 2.5 seconds or less
- Interaction to Next Paint: 200 milliseconds or less in field conditions
- Cumulative Layout Shift: 0.1 or less
- No severe long tasks or unnecessary main-thread blocking

Do not manipulate or “game” Lighthouse by hiding content, disabling necessary functionality or removing important third-party features.

If an essential third-party service prevents a target from being reached, identify the service, quantify the impact and recommend the safest next step in the final report.
